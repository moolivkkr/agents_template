## Narrowed

**TEST-08 (INCOMPLETE passes the gate) → MEDIUM.** The non-security INCOMPLETE pass is what the
protocol describes (debate-protocol.md:141-142, 276-282: a flagged outcome for the checkpoint),
not a missing check; and the security INCOMPLETE-with-no-hardened-option case already fails the
gate, as INVALID (reproduced, see ARCH-10). What remains: a security INCOMPLETE that does name a
`hardened_default` passes with a note only, there is no machine signal that maps to `run.json`
`awaiting_human`, and under `/autonomous` nobody reads the notes (ARCH-04).

**ARCH-14 (moderator's non-COMPLETE returns unhandled) → MEDIUM.** The orchestrator's generic
`NEEDS_INPUT` row (develop-orchestrator.md:283: ask the user, relaunch the same agent with the
answers) does apply to the moderator, so that return is handled. The `BLOCKED` returns (invalid
request, already decided by a D-NNN, wrong depth) are not, and the 0c re-spawn loop is as
described.

**ARCH-03 (remember.sh decide race) → HIGH, narrowed on "silently".** The race, the lost ledger
entry and the duplicate D-NNN all reproduce (20/20 trials lost an entry). But in 17/20 trials one
caller crashed with a Python traceback on the shared `.tmp` name, which the arbitrator would see
and could retry; the silent case (both print `D-002 recorded`, one entry gone, `promoted()` passes
on the other topic's heading) occurred in 3/20 trials.
