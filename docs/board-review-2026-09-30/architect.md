# Architect review — coding and testing agents (startup-agents)

Reviewer hat: ARCHITECT. Scope: 22 agents (10 templates, 12 core). Repo read-only. All citations are `file:line` in `<repo>` (paths under `.claude/` unless noted), read in this session. "orch" = `.claude/commands/develop-orchestrator.md` (the canonical executor, per `commands/develop.md:119`).

## Verdict

1. **Make one machine-readable API contract the only source of truth, and gate on it before UI work starts.** Today the success envelope, pagination and error shape are defined in at least 8 incompatible ways across the agents and the skill packs they load (ARCH-01), and the auth/session model differs per client (ARCH-02). The web UI binds to the planning doc while the mobile UI and every test mock bind to a hand-written as-built doc (ARCH-04). The implementer then writes that as-built doc into the spec folder the reconciler trusts (ARCH-05). The contract gate that exists (`develop-steps/step-2-5`) is never run by the orchestrator.
2. **Redraw the coding boundaries and give the runtime contract an owner.** backend_developer and api_developer both write handlers and middleware. Three agents write migrations, with two incompatible naming schemes (ARCH-03). No coding agent builds what the k8s layer requires: `serve/migrate/seed` subcommands, `/healthz` + `/readyz` + `/api/version`, and a read-only filesystem (ARCH-10). The migration authors are taught reversible DOWN migrations, while the deploy layer is forward-only with old pods still serving (ARCH-11).
3. **Fix the hand-offs that silently don't exist, and the test that claims to catch them.** Nobody writes `ui_developer/manifest.json`, yet two agents require it (ARCH-08). Nobody writes `e2e_workflows_unlocked`, yet it is e2e_orchestrator's only input (ARCH-07). Nobody writes `migrations_applied` or the schema tables into the phase manifest (ARCH-19). `tests/lib/depgraph.py` can't see this class of gap because fnmatch's `*` matches `/`.
4. **Wire the test tiers to the environment the gate certifies.** Browser E2E runs before the deploy wave. `APP_BASE_URL` is exported into a throwaway shell that no agent reads. Acceptance, mobile and a11y all hard-code `localhost:8080/health`. So "tested on qa digests" isn't true (ARCH-09).
5. **Stop hard phases from bypassing the architecture, and strip stack and project leakage out of the templates.** Candidate mode, which is automatic for every PLATFORM phase, replaces all role agents with generic implementers, and the gate can then only pass on fabricated completion lines (ARCH-06). The templates are hard-wired to React, Go and Vertix despite the factory offering Vue, Angular and Python (ARCH-13, ARCH-14). The "mandatory" optimizers are not wired into the orchestrator, and their rules license changing tests, contract mocks and architecture (ARCH-15, ARCH-16).
