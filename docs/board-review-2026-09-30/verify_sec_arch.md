## Refuted or overstated

**SEC-01 (CRITICAL → HIGH).** The mechanism is exactly as described:
- Security blockers are force-gatable under `/autonomous` after 3 cycles.
- Cycle 3 invites "simplify/skip".
- `verify-gate.sh` exempts only an incomplete roster.
- The step-6 doc even uses a security IDOR as its sample forced blocker.

"Ship without a human seeing it" is overstated:
- The checkpoint text states the force-gate policy.
- Forced blockers become CRITICAL carry-forward items in the next phase.
- They appear in the final Autonomous Run Report ("Forced gates: N", Known Issues) and the `/accept` release notes.
- The release is tagged `-rc.1`, not `v1.0.0`, and `/autonomous` only deploys locally.

The human sees it before any real release, but only after the fact and without a security-specific stop. HIGH is right. The fix direction (security blockers PAUSE instead of force) is sound. Also make the "2 consecutive forced gates" limit mechanical: it is prose only today.

**SEC-02 (CRITICAL → HIGH).** Confirmed: unattended `npm/pip/go get/brew install` is pre-allowed, lifecycle scripts are never disabled, and there is no pre-install vetting. Downgraded because:
- The cited statistic is misquoted (19.7% of package *references*, 2024 models); newer frontier models hallucinate package names less often, though not never (arXiv 2605.17062).
- The attack needs an attacker to have pre-registered the exact hallucinated name.
- This is workstation hygiene in the human-applied settings script, not a flaw the coding agents introduce into the product.

The impact if it does happen (full user-account compromise) justifies HIGH, not CRITICAL. Recommendation (3), lockfile-only installs, is the cheapest high-value fix.

**SEC-04 (HIGH → MEDIUM).** The provenance gap is real and worth fixing:
- `remember.sh` defaults every entry to `human`/`confirmed`, contrary to its own protocol.
- The SessionStart injection ignores confidence.

The exploit, however, needs a prior compromise (SEC-03) or an agent writing a false security decision. security_reviewer's "do not re-litigate" is qualified by "without new evidence … append a reversing entry or escalate", and a live unauthenticated route is new evidence. This is an amplifier of SEC-03, not an independent entry point.

**SEC-11 (HIGH → MEDIUM).** The acceptance template prefers `POST /api/v1/seed` with no auth header, and nothing bans such a route in release builds; that part is confirmed. But no agent is told to build the route, the template falls back to the migration seeder, and the k8s layer the finding cites seeds through a CLI `seed` subcommand (the safe pattern). The harmful outcome depends on an agent inventing an unauthenticated route and security_reviewer's Check 11 missing it. A cheap fix is still warranted: "seed only via CLI; any HTTP seed route must be excluded from release builds".

**SEC-14 (HIGH → MEDIUM).** The text does say "Frontend AI Service Layer … fallback … direct LLM" with hosted providers, and no rule treats model output as untrusted. The section is conditional on a project with an AI service, is Vertix-specific (`composer-ai-service/`), and "direct LLM" may mean local Ollama. Downgraded for reach, not merit. Deleting the section fixes this, DEV-14 and ARCH-14 together.

**ARCH-01 (CRITICAL → HIGH).** The many incompatible envelope definitions are real. Worse, `integration_test_agent`'s "data, error, meta (no extra, no missing)" rule fails against api_developer's own list shape. But api_developer does name a winner (`data-contracts.md`, drift = BLOCKER), and UI and mobile mocks copy the as-built `api-contracts.md`. Most outcomes are loud (failing contract tests, Wave-5 churn), not silently broken shipments. It is a systemic quality and throughput problem, not a CRITICAL correctness or security hole.

**ARCH-02 (PARTIAL → MEDIUM).** "No agent owns the auth/session model" is wrong: IMPLEMENTATION_GUIDELINES §4.1/§4.5 hold it per project (auth method, token storage, lifetimes, session store), filled at `/init`. The template's own example "secure localStorage" is a problem, and belongs with SEC-08. The architectural residue is that ui_developer's reference code contradicts the guidelines and its reading list ignores §4.
