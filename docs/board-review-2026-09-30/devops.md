# DevOps review — coding + testing agents (startup-agents)

Reviewer hat: DevOps / platform. Scope: the 22 coding/testing agents, judged against the /develop pipeline, the k8s dev/qa lab layer and CI. Every citation below was read in this session. I ran four commands to confirm behaviour directly: BSD `grep -P`, GNU `find -perm +111` in a local Ubuntu 22.04 image, and a `docker build` + `docker run` of the `USER` line from `docker.md`, plus `go version`. I also checked four facts by web search: Go test caching, how the golang Docker image sets `GOTOOLCHAIN`, Postgres `ADD CONSTRAINT IF NOT EXISTS`, and the `@axe-core/playwright` API. Where a finding cites a context file (orchestrator, deploy layer, skills), it's because that file decides whether the agents' output builds or deploys.

## Verdict

1. **Code from the coding agents can't be deployed to the k8s lab, and nothing in /develop fixes that.** The runtime contract lives only in deployment_agent and the k8s templates: `serve|migrate|seed` subcommands, `/healthz` and `/readyz` (with a schema-version check), `/api/version` returning `git_sha`, `DATABASE_URL`/`APP_ENV`, a numeric USER, a read-only rootfs, DB connection retry, and migrations inside the build context. deployment_agent never runs in /develop. A grep of all 22 agents finds none of these terms.
2. **The artifact promoted to qa gets no functional test.** Only `smoke.sh` checks it. Web E2E runs in Wave 3, before Wave 3.5 deploys anything, and targets `npm run dev` on `localhost:3000`. Acceptance checks `localhost:8080/health`. Mobile targets host loopback. `APP_BASE_URL` is exported once in the parent shell and never passed to any agent. Wave 5 fixes are never redeployed, and the gate never compares qa's `git_sha` with HEAD.
3. **The "independent" test re-run isn't independent or reproducible.** test_runner's Go commands hit the Go test cache and don't print test counts. Its Jest, pytest and cargo fallbacks error out unless extra setup exists that no agent creates. No agent produces JUnit or coverage files CI can consume, except mobile_e2e_orchestrator. IMPLEMENTATION_GUIDELINES has no command table, so each agent and CI infers its own commands.
4. **Local, CI and k8s drift apart everywhere:**
   - Postgres: 16 in testcontainers, CI and compose; 17 in k8s.
   - Go: `golang:1.22-alpine` with `GOTOOLCHAIN=local` in the Dockerfile skills, 1.22 in CI, go1.27.1 on this machine.
   - DB env var: `TEST_DB_URL` vs `DATABASE_URL`.
   - Health path: `/health` vs `/healthz` + `/readyz`.
   - Base URLs: five different ones.
   - Env names: `production` vs `dev|qa` vs `dev/staging/prod`.
5. **Migrations and hygiene fight the forward-only lab.** migration_agent requires every DOWN migration and stores per-environment `applied` state in git. Its idempotency advice includes Postgres syntax that doesn't exist, and it never asks for N-1 schema compatibility, which forward-only rollback depends on. Test waves leave uncommitted files in build contexts, so qa can be promoted from a `-dirty` image that matches no commit. Acceptance and integration data build up in qa across phases, and nothing resets it per phase.
