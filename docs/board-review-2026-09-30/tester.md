# Tester (QA lead / test architect) review: coding and testing agents

Scope: the 22 agents listed in the brief, read against `develop-orchestrator.md`, `verify-gate.sh`, `skills/testing/*`, `gate-verification.md`, `change-impact-analysis.md`, `adaptive-replan.md` and `lima-k8s-lab.md`. Every citation below is from a file read in this session. Two claims were checked by running the framework's own code on synthetic inputs in the scratchpad (no repo file was touched):

- **Gate simulation** (`scratchpad/gatesim`): the real `.claude/hooks/verify-gate.sh 1` was run against a phase containing `unit_tests.md` = "Total: 120 | Passed: 110 | Failed: 10", an `e2e_results.md` with a FAIL workflow row, and an `acceptance_report.md` = "Summary FAIL, 3/10 use cases passed, CONTRACT_VIOLATION = BLOCKER". The roster had no `test_runner`, `spec_test_reconciler`, `integration_test_agent` or `acceptance` sidecar, and `manifest.gate.passed=true`. **Result: `RESULT: ✅ PASS — Phase 1 gate evidence is complete and honest.` EXIT=0.**
- **TC-* inventory simulation** (`scratchpad/tcsim`): the exact Step 0 commands from `spec_test_reconciler.md:51-79` were run on a phase-2 spec with TC-API-001, TC-API-002, TC-SEC-003 and "TC-E-106 to TC-E-115". The only annotations were a phase-1 test reusing TC-API-001, a `t.Skip()` test carrying TC-API-002, a `// TODO TC-SEC-003 not implemented yet` comment, and one comment listing TC-E-106 and TC-E-115. **In zsh (grep = ugrep with -P): MISSING = [] (100% "covered").** **Under `bash` with the macOS system grep (BSD, no -P): SPEC_IDS empty, SPEC_COUNT = "0\n0", so the reconciler takes the "No TC-* IDs found in specs — skipping inventory check" branch.**

## Verdict

1. **The deterministic gate cannot see test failures.** `verify-gate.sh` passed a phase with 10 failing unit tests, a failing e2e workflow and a FAILED acceptance run. Its markdown fallback checks only `total: 0`, `SKIPPED` and `BLOCKING`, and only `test_runner` writes a JSON sidecar with `failed`. `test_runner` is also not in the mandatory floor (TEST-01, TEST-04).
2. **TC-* traceability measures whether an ID string appears somewhere, not whether behaviour was tested.** Skipped tests, TODO comments, earlier-phase tests with recycled IDs, and range endpoints all count as covered. Scanner errors are hidden by `2>/dev/null` and turn into "skip the inventory check" (TEST-02, TEST-17).
3. **The code that gets gated is not the code that was tested or deployed.** `test_runner` runs once (Wave 3v). Wave 4 and Wave 5 fixes are verified only by the agent that made them, the app is not redeployed, the canonical Wave 6 regression step is comments only, and the execution-grounded check (e) is opt-in with nothing that ever enables it (TEST-03).
4. **Nothing measures whether tests can fail.** There is no mutation testing, no red-first step for feature tests, and coverage is self-reported and unenforced. Oracles come from the implementation (unit tests are written from source, contract tests from the implementer's "as-built" `api-contracts.md`). Agents that write tests may also edit production code and tests, and nothing detects deleted assertions, skips or `.only` (TEST-06, TEST-07, TEST-08, TEST-14).
5. **Environments and flake policy make green results unreliable.** Web e2e (Wave 3c) runs before the phase is deployed (Wave 3.5), and no test agent is given the QA URL. "FLAKY" is routed to "fix the test, re-run only that tier". NFR-PERF and TC-SEC-* never reach any gate (TEST-09, TEST-10, TEST-12, TEST-13).
