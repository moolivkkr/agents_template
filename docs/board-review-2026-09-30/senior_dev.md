# Senior Developer Review — coding and testing agents (startup-agents)

Reviewer hat: senior developer. Date: 2026-09-30. Repo read-only; every citation below was read in this session.
Paths are relative to ``. "Orch" = `.claude/commands/develop-orchestrator.md` (the canonical executor per CLAUDE.md).

## Verdict

1. **Stop the optimizers from editing tests and mocks, and stop them treating green tests as proof that code is dead.** `code_optimizer` and `ui_code_optimizer` are told, in so many words, to "Update test expectation" and "Update mock to match optimized component's expectations". They are also told that "if they pass after removal, it's dead" and to delete "error handlers for errors that cannot occur". Taken together, that is permission to change behaviour and then relabel the change as correct. The optimizers also don't appear in the canonical orchestrator at all, and their scope lock is broken (DEV-01, DEV-06, DEV-07, DEV-21).
2. **Put a compile, typecheck, lint and test gate back into canonical Wave 2, and make every coding agent's Definition of Done name the commands.** The legacy step file had blocking compile gates between backend and API work. The orchestrator dropped them. Today the first objective build signal is a *test-writing* agent in Wave 3, and those agents are allowed to "fix the component" (DEV-02, DEV-09).
3. **Define one API envelope and delete every contradicting example.** Seven agent or skill files show at least five different success and pagination shapes. `ui_test_agent`'s own "✅ CORRECT" mock doesn't match `api_developer`'s envelope. That is exactly the UI↔API drift that `api-contracts.md` was built to prevent (DEV-03, DEV-18).
4. **Make the implementers work *in* the existing codebase and to its runtime contract.**
   - No coding agent reads the Wave 1 audit report.
   - None has a minimal-diff, read-before-edit or follow-existing-conventions rule.
   - `backend_developer` also writes migrations, handlers and tests that other agents own.
   - None of them knows the lab cluster needs `serve`/`migrate`/`seed` subcommands, `/readyz` and `/healthz`, a read-only root filesystem, and forward-only schema changes.

   (DEV-04, DEV-05, DEV-10)
5. **Give the fix agents the same discipline as the authors, and re-test after every fix.** Wave 4 and Wave 5 fix agents are untyped general-purpose agents with a five-line prompt. They get no skill packs and never see the Test Failure Recovery Guardrails. Wave 4 fixes are "verified" only by re-running the reviewer, and the Wave 6 regression step is comments with no command (DEV-08). The candidate-selection path (Wave 2B) can't satisfy the roster or the downstream contract inputs either (DEV-11).
