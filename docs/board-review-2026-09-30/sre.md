# SRE review: coding and testing agents (startup-agents)

Reviewer: SRE seat. Date: 2026-09-30. All paths are relative to the repo root `<repo>`. Line numbers come from files read in this session. Web-verified claims carry their source URL in the cell.

## Verdict

1. **The rollback and migration path is where production is most at risk.** For local, staging and prod, `/rollback` runs DOWN migrations before it redeploys the old build, and it spawns `migration_agent` with `prisma migrate reset` as an example command. That command drops the whole database. The migration author is taught lock-taking DDL as "safe" and is never taught expand/contract. Meanwhile the k8s deploy script starts the new pods before the migration job has run.
2. **The SRE agents never reach the code during `/develop`.** No wave spawns `reliability_agent` (it only appears in a roster rule). `performance_agent` is optional and its own body says to *recommend* a load test rather than run one. `verify-gate.sh` checks nothing about reliability, performance, observability or the deploy verdict. None of the 22 agents reads the SLOs, error budgets or runbooks, so they exist only on paper.
3. **The skill packs the coding agents actually load teach production anti-patterns:**
   - retries on timeouts and 5xx with no idempotency condition;
   - `tenant_id` plus the raw URL path on every metric;
   - an optional cache inside readiness;
   - closing the listener on SIGTERM with no preStop delay;
   - a separate connection pool per tenant.

   The correct versions sit in per-language archetypes that no agent loads.
4. **No test tier ever exercises failure.** Nothing tests a dependency that is down or slow, a timeout firing, a circuit breaker opening, SIGTERM under load, a pod kill or a DB restart. The unit agent is told to skip "infrastructure glue", and the integration agent is told to treat a DB outage as an environment error. The disposable dev/qa cluster only gets happy-path smoke checks.
5. **The test harness turns nondeterminism into green.** Web E2E retries silently, a pass on retry is routed as "FLAKY, re-run failing tier", and flaky tests are quarantined with `t.Skip` in a way that can never lift. Nothing runs the race detector, repeats a suite, or puts a timeout on a suite. `mobile_e2e_orchestrator` is the one agent that handles this correctly.
