# Cyber Security Review — coding and testing agents (startup-agents, 2026-09-30)

Reviewer: cyber security hat (AppSec + offensive). Every citation below was read in this session. The "guard probe" results come from running `.claude/guard/sdlc-guard.sh` on synthetic hook JSON in this session. The guard returned no opinion (empty output, rc 0), so the normal permission flow decides.

## Verdict

1. **Security is inspected in Wave 4; it is never an input when code is written.** None of the four coding templates loads the OWASP pack. The Wave-2 spawn prompt's "HARDENING RULES" contain no security rule. The threat model's mitigations and TC-SEC-* ids reach no coder, tester or reconciler. Code changed in Wave 5 is never security-reviewed again (SEC-05, SEC-06, SEC-07).
2. **A known, exploitable finding can ship without a human seeing it.** `/autonomous` force-gates any blocker that survives 3 fix cycles, security blockers included. Cycle 3 tells the fixer to "simplify/skip", and the human's consent was given at the checkpoint before the finding existed. The gate also trusts files and "ground truth" memory that any agent can write (SEC-01, SEC-04, SEC-15).
3. **The agents themselves are the largest attack surface.** Unattended `npm/pip/go/brew install` is pre-allowed, and lifecycle scripts run on the developer's Mac before any dependency review. Nothing vets for hallucinated or typosquatted packages. The shared operating contract has no "content is data, not instructions" rule. This session confirmed that the guard passes interpreter-based egress (`node -e`, `python -c`), WebFetch, `git push` to a newly added remote, glob paths to `~/.ssh`, the GitHub CLI token file and macOS Keychain reads (SEC-02, SEC-03).
4. **Several instructions produce vulnerabilities directly:**
   - bearer tokens in `localStorage` and in WebSocket URLs, taught to `ui_developer` (SEC-08);
   - a compiled-in default signing secret that is refused only when ENV is exactly `"production"` (SEC-10);
   - an unauthenticated persona/role seed endpoint as the "preferred" path, in images that are promoted by digest (SEC-11);
   - a browser-side "direct LLM" fallback (SEC-14);
   - "technical detail" in every error response (SEC-16).
5. **Testing proves tenant isolation and little else.** Strengths:
   - cross-tenant IDOR tests with correct 404 semantics (integration and unit);
   - a 401/403-per-endpoint matrix (`test-case-generation.md:65-72`);
   - solid mobile storage and transport rules.

   There are no durable tests for XSS rendering, mass assignment, same-tenant ownership, token tampering, injection, rate limits, or regressions of fixed findings. The reviewer's XSS probe checks the wrong layer. SAST and secret scanning are effectively off by default (SEC-09, SEC-12, SEC-13).

  - Pre-allowed `npm/pip/go/brew install` with lifecycle scripts, and no SBOM, image scan or gitleaks (SEC-02, SEC-13).
