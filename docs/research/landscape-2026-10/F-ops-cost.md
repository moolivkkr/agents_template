# Track F: operating agent pipelines (observability, evals, cost, MCP/A2A, DevOps)

Checked 2026-10-02. Repo facts come from `git show main:<path>`. Every external claim has a URL and was checked on 2026-10-02 unless marked unverified.

## Bottom line

Cost and quality signals are already available to us for free. Claude Code itself exports per-request cost and tokens over OTel, labelled with `agent.name`, `skill.name`, `effort`, `query_source` and `workflow.run_id`. We don't collect any of it. Our phase ledger records `total_tokens` per spawn but no dollars, no model, and no cache split. Our `/eval` runs each task once, with a fixed ±0.05 noise band and deterministic rubrics only. It has no k-trial reliability (pass^k) and no calibrated judge for the judgement agents (reviewers, debate arbitrator). DevOps for the apps we build stops at dev/qa digest promotion. There are no per-PR preview environments, no metric-gated canary, and no DORA numbers, even though the stack (k3s, `deploy.sh`) could support all three.

## 2. Strongest recommendations

**R1. Collect Claude Code's own OTel locally and join it to the phase ledger (H value, S effort).**
What we'd build: `scripts/telemetry-up.sh` starts an `otel-collector` container (file exporter writing JSONL to `agent_state/telemetry/`, no vendor). `/develop` and the supervisor export `CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_LOG_TOOL_DETAILS=1` and `OTEL_RESOURCE_ATTRIBUTES=phase=<N>,project=<name>,run=<id>`. `ledger.py report --cost` then prints USD, tokens and cache-read % per phase × agent.name × model × effort. That shows what a wave, a Fable retry and a candidate-selection round actually cost.

**R2. Cost governance in the orchestrator, built on R1 (H, S–M).**
What we'd build: per-phase and per-wave budgets in `agent_state/config/budgets.json`, with a warn at 80% and a stop-for-ruling at 100%. This extends the supervisor's whole-run `max_cost_usd` down to the wave level. Two checks are added. Candidate selection (N=2–3) is allowed only if its projected cost stays under the wave cap. A `cache_read_ratio` below a threshold for an agent flags prompt-order drift (Opus 5.5 cache reads are 0.05×, so a cache miss costs 20× on the prefix). Gate verify-gate.sh on nothing here at first (warning-first, D-002).

**R3. Eval reliability: k trials plus a calibrated judge set (H, M).**
What we'd build: (a) `/eval --compare --trials=3` reports pass@1, pass^3 and per-task variance. The noise band becomes the measured variance from the baseline's trials instead of a fixed ±0.05. (b) `agent_state/eval/judge/`: about 30 human-labelled findings (true IDOR, false positive, style nit mislabelled as blocking), drawn from real rera review reports. A `judge-calibration` run scores code_reviewer_II, security_reviewer and debate_arbitrator against the labels: precision/recall, plus Cohen's κ vs the human. Disagreements become few-shot examples, the Align Evals pattern. Rerun on any reviewer prompt change.

**R4. Per-PR preview environments on the lab (M–H, M).**
What we'd build: `deploy.sh preview <pr#>` creates namespace `<app>-pr-<n>` from the PR's image digests and runs db-roles → migrate → seed → rls-check → smoke. A TTL label (e.g. 48 h) gets swept by a cron job, with at most 2 concurrent previews. acceptance_test_agent and e2e_orchestrator can point `APP_BASE_URL` at it, so qa stays clean. The Argo CD PR generator is the same idea, declarative. Adopt it only if we move to GitOps.

**R5. Pipeline DORA from deploy evidence (M, S).**
What we'd build: `scripts/dora.py` reads existing deploy evidence + git. It computes lead time (commit → qa healthy), deploy frequency, change fail rate (deploys followed by `/rollback` or `/hotfix`), recovery time, and **rework rate** (hotfix deploys ÷ all). The output feeds `/worklog` and `/status`. AI-assisted delivery reportedly raises instability (see unverified), and these numbers are how we'd see it in our own pipeline.

## 3. Don't copy

- **A hosted tracing SaaS as a dependency (Braintrust, LangSmith cloud).** Code and prompts would leave the machine, which the owner's rules treat as outside-network. An OTel file exporter gives 80% of the value. Langfuse/Phoenix self-host is a fallback only if we want a UI. ClickHouse + S3 is a lot for one Mac.
- **Their Claude Code plugins/hooks (Langfuse, Arize).** Supply-chain rule. Our own ledger hook already sits in the same place.
- **A2A.** Fine as a standard, but it solves cross-vendor, cross-process agent RPC, and we have none of that.
- **A third-party MCP gateway/registry.** We use ~1 MCP server, and FRAMEWORK_REVIEW §2 already settled on CLI over MCP.
- **A cheaper-model cascade across the pipeline.** `model-routing.md` deliberately keeps one model (one cache namespace) and escalates on evidence. The pricing check supports this: on Opus 5.5 the cached prefix is 0.05× input, so splitting families forfeits that. Revisit only if R1 data shows a specific mechanical agent dominating spend, then A/B it with `eval-question-tokens.py`.
- **Argo Rollouts on the lab.** No real traffic, so analysis runs would gate on noise.
- **A shell-only `OTEL_LOG_RAW_API_BODIES` "replay".** Useful for one-off forensics, but it writes full code and secrets to disk. Never default it on.
