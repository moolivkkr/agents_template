# Track B: general agent-orchestration frameworks, and what the phase ledger and supervisor should borrow

Checked 2026-10-02. All sources were fetched on that date unless a line says otherwise. Our side was read from `main`: `docs/PHASE_LEDGER.md`, `docs/AUTONOMOUS_GUIDE.md` §3–4 and §10, `docs/FRAMEWORK_REVIEW_2026-09-30.md` §2–3 and §5, `.claude/skills/core/child-returns.md`, and `.claude/commands/develop-orchestrator.md`.

**Scope note.** The 2026-09-30 review compared us only with Claude Code SDLC frameworks (superpowers, spec-kit, GSD and others). None of the general orchestration frameworks below appear in it (`git grep` over docs and .claude finds no LangGraph, Temporal, CrewAI, DBOS, Inngest, Restate, Mastra or A2A; one Letta mention is in `consolidate.md`). This track is therefore new ground. We should not adopt any of these frameworks as a runtime: our agents are Claude Code subagents, not SDK agents. What is worth taking is their execution semantics, which map closely onto ledger steps 2–3 and onto the supervisor.

## 2. Strongest recommendations

**R1. Ledger step 3a: a SubagentStop "result guardrail" that records completion from code.** (Borrows CrewAI guardrails and `guardrail_max_retries`, PydanticAI `ModelRetry`, and OpenAI tripwires. Closes the open B7 item, hook-written completion.)

What we'd build:
- Each agent ends with its existing first line plus a fenced `RESULT` JSON block (`status`, `task`, `outputs[]`, `evidence[]`).
- The `ledger.py` SubagentStop handler parses `last_assistant_message`. It validates the block against a per-agent-type schema in `agent_state/config/result-schemas/`, and checks that each declared output exists and was modified after `started`.
- On failure it returns `decision: block` with the exact error, at most `max_retries` times (default 2, counted in ledger state). After that it lets the subagent stop and writes `finished{status:"guardrail_failed"}`.
- It writes `completed` only when validation passes. Agents stop writing their own `execution.jsonl` lines.
- Rollout: warning-only first (log the would-block), per D-002.

**R2. Ledger step 2: `plan.json` as a memoized task state machine, not just a DAG.** (Borrows A2A task states, MAF superstep checkpoints with stable executor ids, and Temporal/Inngest/Workflow-tool memoization.)

What we'd build:
- Task: `{id, agent_type, depends_on, inputs_hash, expected_outputs, state}`. The states are A2A's: `submitted | working | input_required | completed | failed | canceled | rejected`.
- `inputs_hash` covers the relevant spec files, `facts_v`, `decisions_v` and the base sha.
- On resume, a `completed` task whose `inputs_hash` still matches is skipped. A changed hash marks it and every dependent `stale`. This is the "longest unchanged prefix" rule, applied per task instead of per wave.
- Task ids must be stable across `plan_version` bumps, because MAF refuses rehydration when executor identities change.

**R3. Ledger step 3b: three clocks per task instead of "no finish after N minutes".** (Borrows LangGraph `TimeoutPolicy` run/idle and Temporal Schedule-To-Start and heartbeat timeouts.)

What we'd build:
- `schedule_to_start`: spawn requested but no `started` after X s, which the ledger already reports as "spawns with no subagent start".
- `idle`: no `files`, `bash` or `todos` event from that agent id for Y min. Progress is refreshed by events the ledger already records.
- `run`: a hard cap set to p95×k of that agent type's historical durations, taken from `ledger.py report` medians and maxima.
- The board shows which clock tripped. The supervisor (§10) gains a `stalled_task` reason that it can act on, instead of only whole-session stalls.

**R4. Typed error handlers and the bounded fix ladder in `plan.json`.** (Borrows LangGraph `NodeError` → `Command` routing and the OpenAI Agents SDK `invalid_final_output` / `max_turns` handlers.)

What we'd build:
- Each task carries `retry: {max_attempts, on: [guardrail_failed, timeout_idle, …]}` and `on_exhausted: {route_to: <task or agent_type>, record_as: ruling|blocked}`.
- The orchestrator, and later the hook, apply it mechanically. This replaces "Max 3 iteration cycles" prose and gives the open fix-ladder and rulings-ledger items one schema.

**R5. Typed human requests for `awaiting_human`.** (Borrows Mastra `suspendSchema`/`resumeSchema`, CrewAI `@human_feedback(emit=…)`, and MAF pending requests inside checkpoints.)

What we'd build:
- `agent_state/autonomous/pending_requests.json` entries: `{id, task, question, options[], answer_schema, default, cost_if_wrong}`.
- Supervisor exit 10 prints them. `--answers <file>` lets a human answer offline and relaunch.
- Resume validates the answers before continuing.
- Apply LangGraph's lesson: a step resumes from its start, so everything before the pause must be idempotent.

## 3. Things we should NOT copy

- **Adopting LangGraph, MAF, ADK, CrewAI or Temporal as the runtime.** Their agents are SDK agents with their own model loop. Ours are Claude Code subagents with hooks, permissions and worktrees. The Temporal and Restate integrations target the OpenAI Agents SDK or Vercel AI SDK, not Claude Code sessions. We'd be rewriting the framework and adding a server, a Postgres instance or Cosmos DB, for semantics we can get with a ~300-line hook. Per the supply-chain rule, borrow the semantics only.
- **Parallel-mode guardrails.** OpenAI documents that the default parallel input guardrail can let the agent spend tokens and run tools before the tripwire fires. Our checks should block (or warn), never race.
- **LLM-judged guardrails as gates** (CrewAI string guardrails). Same-model judging is what our board-review verifiers were built to avoid. Use deterministic validators, and send LLM judgment to the existing reviewers.
- **Time-travel replay of LLM steps.** LangGraph itself warns that replay re-executes LLM calls and may differ. Git plus the ledger gives us inspection, and `/reset-phase` gives us forks.
- **Live-mutable shared memory blocks** (Letta). Concurrent writers with no supersession history would weaken our bi-temporal Tier 0 model. We already borrowed the useful idea, sleep-time consolidation (`/consolidate`).
- **Pickle-based checkpoints** (MAF Python file and Cosmos stores, even with a restricted unpickler). Stay with JSON.
- **DSPy/GEPA now.** It needs a large labelled metric set. The headline numbers are paper and vendor claims. Revisit later, if at all, for one narrow, high-volume agent such as code_reviewer_I, with a real eval set.
- **A2A transport.** It solves cross-organisation agent interop, which we don't have. Take the state names only.
- **OTel GenAI conventions as a target format.** They are still Development status, so keep any export optional.
