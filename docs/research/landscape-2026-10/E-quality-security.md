# Track E — Quality, verification and security of AI-generated code

All sources checked 2026-10-02. Repo claims checked against `main` with `git show`/`git grep`.
Vendor numbers are labelled as vendor claims.

## 0. Repo facts this track rests on (verified on main)

- **Reviewer findings are not verified before the fix loop.** `security_reviewer.md` and the `code_reviewer_*.md` files require `file:line` evidence. No step tries to refute a reviewer finding before it is sent for fixing. Cross-model refutation exists only at the gate, for "PASS/fixed" claims (`develop-orchestrator.md` Wave 6, Layer 3), and in `/board-review` (blind verifiers). No reviewer separates *pre-existing* from *introduced* findings (0 matches for "pre-existing" in the three reviewer files).
- **Mutation testing is advisory.** `test_runner.md` §9 reports surviving mutants as WARNINGs. Nothing turns survivors into tests. The unit template already sets "the oracle is the spec, not the code" and red-first (`unit_test_agent.tmpl:57,127`), which matters, as §1 shows.
- **The guard sees commands, not processes.** `docs/PERMISSIONS_GUIDE.md` ("Limits, stated plainly") says sdlc-guard does not catch network I/O from script files, package install scripts, `npx`, or code built at runtime. Agents are told to run `vet-package.py`, but the guard doesn't enforce it. There is **no OS sandbox config**: `git grep sandbox` finds nothing in the guard or settings.
- **vet-package.py checks the age of the package, not the version.** It looks only at the first-publish date (`created`). A brand-new malicious version of an old, popular package passes. No `min-release-age`, `minimumReleaseAge` or `exclude-newer` cooldown appears anywhere in `.claude/` or `docs/`.
- **Our own archetype ships the pattern that the Trivy compromise exploited.** `.claude/skills/backend/archetypes/dockerfile-go.md:451` has `uses: aquasecurity/trivy-action@master`, and 19 other `uses:` lines in skills are tag-pinned. Yet `skills/infrastructure/github-actions.md:115` itself says to pin third-party actions to a commit SHA.
- **No provenance or signing for images.** `sbom|cosign|attest` appears only as a one-line "use SBOM in CI" in `security-owasp.md:59`. Digest promotion exists, but nothing checks who built the digest.
- **No security guidance for products that include LLM features.** "OWASP LLM / agentic" appears only under `rule_board/ai_security/` (detection rules), not in `security_reviewer` or `threat_model_agent`. "MCP" plus "poison/security" returns 0 matches.

## 2. Strongest recommendations

**R1. OS sandbox + credential deny for unattended runs (`/autonomous`, Wave 3 writers). H value, M effort.**
What we'd build: `apply-user-settings.py --sandbox` writes `sandbox.enabled`, `allowUnsandboxedCommands:false` and `failIfUnavailable:true` into user/managed scope. It also writes `network.allowedDomains` = the package registries, github.com, the lab hosts and `*.localhost`; `credentials.files` deny for `~/.ssh`, `~/.aws`, `~/.kube/*` except the agent kubeconfig; `credentials.envVars` deny for tokens; and narrow `excludedCommands` for `docker compose`/`limactl` only. sdlc-guard stays as the command-semantics layer (namespaces, prod), and the sandbox becomes the process-level boundary that closes the gaps in PERMISSIONS_GUIDE "Limits". Add a guard test that an install script's `curl evil.example` is blocked.

**R2. Supply-chain catch-up: version cooldown, SHA-pinned actions, enforced vetting. H value, S effort.**
What we'd build: (a) `impl_guidelines_agent` / archetypes emit `min-release-age=7` (npm `.npmrc`), `minimumReleaseAge` (pnpm), and `exclude-newer = "7 days"` (uv), with a documented security-fix exemption list. (b) `vet-package.py` also checks the publish time of the *resolved version* (npm `time[version]`, PyPI per-release upload time). (c) Fix `dockerfile-go.md:451` and every `uses:` in skills to `@<40-hex>  # vX.Y`, and add a skills-harness test that fails on any non-SHA third-party `uses:`. (d) `dependency_scanner` fails new deps whose vet was never recorded.

**R3. Verify findings before the fix loop (precision pass). H value, S–M effort.**
What we'd build: between Wave 4 and Wave 5, a `finding_verifier` step on a different model (reuse the board-review blind mechanics) gets each BLOCKING/HIGH finding without its severity. It must reproduce it (a failing test, a request, or a traced `file:line` path) or mark it REFUTED. Refuted findings go to `agent_state/phases/N/reviews/refuted.jsonl` and never enter Wave 5. Reviewers add `introduced | pre-existing` to every finding; pre-existing findings go to the backlog, not the fix loop, unless they are security findings. After round 1, nits are suppressed.

**R4. Reviewer rule lifecycle from fix-loop outcomes (Bugbot-style). M value, M effort.**
What we'd build: every finding gets a `rule_id` (checklist item). `/consolidate` tallies per rule how often it was refuted, waived or fixed across phases. A rule refuted at least 3 times with no fix becomes `disabled` (with `retire_when` recorded), and a recurring human-caught miss becomes a `candidate` rule. This uses the existing procedural-promotion and `applies_when/retire_when` open item, so no new store is needed.

**R5. Mutation-guided tests for security-critical code + LLM-features threat model. M–H value, M effort.**
What we'd build: (a) For files tagged authz/tenant/RLS, `test_runner` survivors become blocking work items, and `unit_test_agent` writes tests that kill them (ACH loop). An LLM equivalent-mutant filter labels "equivalent" with a reason; those don't block. (b) When the BRD contains LLM/agent features, `threat_model_agent` adds an OWASP Agentic/LLM section (goal hijack, tool misuse, memory poisoning, excessive agency) with TC-SEC rows, and `security_reviewer` gets the matching checklist. (c) Research/debate agents that fetch the web run without Bash/kube tools (Rule of Two).

## 3. Do NOT copy

- **Hosted review bots as gates** (CodeRabbit/Greptile/Graphite Agent/Bugbot/Claude Code Review). They send code to third parties, cost per PR (Claude Code Review averages $15–25 per review per its docs), and are designed *not* to block (neutral check run). Borrow the techniques (verification step, severity classes, learned rules), not the service. Graphite's "Diamond" brand is gone; it is now Graphite Agent under Cursor (acquired Dec 2025, [Fortune](https://fortune.com/2025/12/19/cursor-ai-coding-startup-graphite-competition-heats-up/)).
- **Vendor precision/recall comparisons.** "Bugbot 78% vs 63%", "Greptile v5 comments addressed 52% → 66%" ([blog, 2026-08-05](https://www.greptile.com/blog/greptile-v5)), "<1% false positives" (third-party blog about Claude Code Review): each is self-measured or an unsourced blog claim. Don't set targets from them.
- **Qodo Cover / coverage-chasing generators.** The repo has been unmaintained since 2025-06, and keeping tests that "pass and raise coverage" encodes actual behaviour as the oracle, which contradicts our spec-as-oracle rule.
- **CaMeL as an implementation.** It is a research interpreter with a utility cost. The cheap 80% of the value is tool scoping (Rule of Two) plus the sandbox.
- **Auto Mode as the security boundary.** Anthropic itself treats it as best-effort (per CSA). Keep it as friction reduction only.
- **SWE-bench numbers as evidence a verification loop works.** Verified is contaminated, and Pro's grading is disputed.
- **Installing third-party "sandbox"/MCP-scanner plugins or pinning bots.** That breaks the supply-chain rule; use first-party settings and hand-written checks.
