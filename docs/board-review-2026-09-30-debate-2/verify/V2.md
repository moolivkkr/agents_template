## Narrowed findings and why

**AI-01 (moderator step 10 reads `problems`, the gate reads `gate`) — HIGH.** Reproduced in all
four states the hat named: unpromoted, same-order second opinion, mis-copied request_sha, pending;
each has `problems: []` and `--check` exit 2. Narrowed on two points: the stale case is not a dead
end, because step 1 (:84-86) re-runs a stale debate on the 0c re-dispatch, so the "return it as is"
stall is limited to the unpromoted and second-opinion-problem states; and the step-10 `jq` prints
the whole topic object including `gate`, so the moderator can see the reason and the defect is the
rule that ignores it. HIGH because the parent acts on this first line and under /autonomous the
result is a stall or a force-gate that leaves the verdict unpromoted.

**AI-19 (T-007 forbidden pattern vs fork mode) — LOW.** The docs confirm the hat's premise verbatim
("Claude Code turns fork mode on by default in interactive sessions ... Claude Code v2.1.232 or
later"; "Claude Code also removes the Agent tool's `run_in_background` parameter"). The pattern
contradicts the required step at :11 and the moderator at :104-111. But eval.md:68 reconstructs the
trajectory from execution logs, manifests and file ordering, which never record Agent-call
parameters, so a scorer following that rule can't apply the pattern to anyone. The penalty needs a
scorer reading the transcript against eval.md:68. Fixture consistency fix, no behaviour change.

**AI-25 (Analysis Paralysis Guard reaches debate agents) — LOW.** The guard text (step-0-orient.md:540,
context-budget-protocol.md:50) exempts only the two audit agents, so it fits every read-heavy agent
badly: reviewers and reconcilers are as un-exempt as the debate agents, so this isn't debate-specific.
And it reaches a debate child only if the /develop parent pastes it into the moderator's prompt and
the moderator into its children's, against the moderator's explicit list of what each child prompt
carries (:113-117, :135-137, :144-152); no hook counts tool calls. Add the exemptions, but as written
it is an unenforced instruction inconsistency.

**AI-22 (labels A–D leak request order past the shuffle) — LOW.** Premise sourced: Zheng et al.
(ICLR 2024, arxiv 2309.03882) attribute selection bias to ID-token bias distinct from position. The
mechanism holds, and the reverse-order second opinion keeps the labels, so a label preference would
not show as disagreement. Narrowed: T-007's two data requests already swap labels along with position
(A is the document store in request 1 and PostgreSQL in request 2), so the hat's "test it in T-007" is
partly present, if confounded with position and only on a MUST-decided case. "Requesters typically
list their preferred option first" is unverified; the repo's own fixtures put the winner at A in one
place and B in another. No wrong instruction and no demonstrated failure.

**AI-29 (cross-topic reopen never gets PRIOR DECISION) — MEDIUM.** The hand-off gap is real
(moderator :82-86 passes PRIOR DECISION only for a stale same-topic verdict; arbitrator :83-85 ties
--reverses to that line). Narrowed because the contradictory case is partly covered: the arbitrator
reads the DECISIONS entries the request touches (:81), Required Reading :35 says to append a reversing
entry when new evidence contradicts one, and step 8 shows `--reverses` "when this overturns a prior
decision". Uncovered is the confirming case: a re-debate that upholds the old decision records a
new active entry without reversing the old one (the stale path reverses "whether you confirm or
change"; the generic rule says "overturns" only). Overlaps ARCH-07; kept separate because the fix is
in the moderator's hand-off.
